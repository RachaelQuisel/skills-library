# Sort My Brain Dump

## Purpose in plain English

This skill helps you organize a collection of thoughts without losing the items that are being deferred.

## How to explain the result

For a client-facing explanation, use ordinary words and the requested format. Explain unfamiliar abbreviations. Name what each number counts and explain its practical meaning. Keep internal identifiers out of the explanation. Keep necessary technical details in the working steps and technical references.

## Following the process

Use the process below. Preserve its conditions, commands, checks, and approval rules. Use information the user already supplied. Follow the existing questions or stopping rules when required information is missing.


Turn the user's supplied notes into a list they can use without losing the items they are setting aside.

## Organize what is present

Accept informal text, fragments, repeated items, and mixed tasks and concerns. Group related items when it improves clarity. Merge genuine duplicates while preserving distinct outcomes and meaningful details. Keep ideas, questions, and worries distinguishable from commitments; do not convert every thought into a task.

Use stated deadlines, dependencies, consequences, available time, and the user's priorities to choose a practical starting point. Explain the recommendation briefly. When information is insufficient, label the starting point as provisional or ask one focused question that changes the choice. Do not invent urgency, dates, owners, priorities, or time estimates.

## Return a manageable view

Usually show one recommended action now, a short next queue, and a compact remainder grouped in a useful way. Treat this as a helpful shape, not a required format. Follow the user's requested structure and level of detail.

Preserve every distinct meaningful input in the output or in an accessible list the user requested. Do not bury or silently drop items to make the visible list shorter. For a long dump, group the remainder or use the host's supported document output when appropriate; keep the result available to the user.

When possible, perform a useful authorized part of the chosen task rather than giving the user another planning assignment. If the user only asks for organization, stop at organization. Do not send messages, create external task records, or schedule events merely because they appear in the dump.

## Continue from corrections

When the user changes a priority or says a deadline is wrong, update that choice and the affected ordering. Preserve other items and avoid restarting the whole exercise.

Honor current preferences for tone, detail, and one step at a time. This workflow does not enable a persistent ADHD mode or claim to store a task list outside the current conversation. If the user wants a saved destination, use the requested supported destination and report what was actually saved.
