# Get Unstuck

## Purpose in plain English

This skill helps you find a manageable first action when a task feels difficult to start.

## How to explain the result

For a client-facing explanation, use ordinary words and the requested format. Explain unfamiliar abbreviations. Name what each number counts and explain its practical meaning. Keep internal identifiers out of the explanation. Keep necessary technical details in the working steps and technical references.

## Following the process

Use the process below. Preserve its conditions, commands, checks, and approval rules. Use information the user already supplied. Follow the existing questions or stopping rules when required information is missing.


Help the user make useful progress on the task they actually want to do.

## Find a workable start

Use the goal, constraints, available materials, and blocker already supplied. Do not repeat intake. If the user has given enough information, offer or perform a useful starting action immediately. If an essential fact is missing, ask one focused question and continue any independent useful work.

Distinguish an unclear goal, a missing input or permission, too many choices, and a task that feels too large. Respond to the observed obstacle; do not diagnose motivation, emotions, or ADHD symptoms. If the user identifies worry or frustration, acknowledge it briefly and keep the help concrete.

Choose a feasible starting action that produces something useful: open the relevant document, find the missing fact, draft the first paragraph, or prepare the first item. Reduce its size if the user says it is still too much. Do not turn every task into an exhaustive list of tiny steps.

When the assistant can create the draft, organize the supplied information, or complete another authorized part of the work, do it. A request to draft a message permits drafting; sending still needs authorization. Do not require a check-in between assistant-executable steps merely because the response is concise.

## Present and adapt

Lead with the useful action or result. Provide ready-to-use material when possible, with visible placeholders for missing facts. Show a short sequence if needed, or just the next action if requested. Explain the choice only when it helps.

Use real stated deadlines and available time. Label reasonable estimates and their uncertainty. Do not promise a timer, future check-in, reminder, or monitoring unless an available tool actually establishes it.

Honor the user's preferred tone and detail. This workflow does not silently enable a persistent ADHD mode. Avoid shame, forced encouragement, and unnecessary questions.

Finish when the requested help or deliverable is complete. If the user asks for more help, continue from the actual progress and preserve the same goal unless they change it.
