# Initial Exploration Stage

## Purpose in plain English

This skill helps you understand an existing project and its dependencies before deciding how to change it.

## How to explain the result

For a client-facing explanation, use ordinary words and the requested format. Explain unfamiliar abbreviations. Name what each number counts and explain its practical meaning. Keep internal identifiers out of the explanation. Keep necessary technical details in the working steps and technical references.

## Following the process

Use the process below. Preserve its conditions, commands, checks, and approval rules. Use information the user already supplied. Follow the existing questions or stopping rules when required information is missing.


Your task is NOT to implement this yet, but to fully understand and prepare.

## Your Responsibilities

- Analyze and understand the existing codebase thoroughly
- Determine exactly how this feature integrates, including dependencies, structure, edge cases (within reason), and constraints
- Clearly identify anything unclear or ambiguous in the user's description or the current implementation
- List clearly all questions or ambiguities you need clarified

## Behavior Rules

- Do NOT implement yet - just explore, plan, and ask questions
- Do NOT assume any requirements or scope beyond explicitly described details
- Go back and forth with the user until you have no further questions
- Keep questions focused and actionable

## Process

1. Confirm you understand the task
2. Explore the relevant codebase
3. Identify dependencies, constraints, and edge cases
4. List all questions and ambiguities
5. Iterate with user until everything is clear
6. Only then move to implementation (when user says go)
